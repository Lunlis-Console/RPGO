## 3. Приоритизированный бэклог по фазам

### Фаза 0 — Заморозка инвариантов (недели 0-1)
- P0-1: убрать `DropAllTables` по условию отсутствия `VersionInfo`. Fail-safe: при отсутствии `VersionInfo` — остановить старт с явной ошибкой, а не дропать; опционально — бэкап файла БД перед любой миграцией.
- Ввести запрет на destructive-миграции без code-review; добавить пре-миграционный бэкап в `DatabaseManager.Initialize`.

### Фаза 1 — БД / безопасность (недели 1-3)
- P1-1: разделить локи game.db и content.db (два `Lock` или per-connection пул); content-риды без блокировки под запись game.db. Рассмотреть ConnectionPool/retry.
- P1-10: убрать двойной тик проектила (оставить единый вызов в unified loop; удалить `ProjectileManager.RunTick` или сделать его единственным источником).
- P2-7: добавить явный лимит соединений; профилировать `BroadcastMapAsync` (delta-обновления вместо полного rebuild).
- P2-6: апгрейд legacy-хеша в PBKDF2 при успешном логине (opportunistic rehash).
- P2-9 часть: монотонная версия (semver-тег, а не commit-count).

### Фаза 2 — Домен Player / типобезопасность (недели 3-5)
- P2-1: ввести enum для `Facing`, `GameMessage.Type` (или discriminated union), `SkillIds` (каталог с enum), zone ID (типизированный идентификатор).
- P2-2: перенести инварианты в модели (value objects: `Health`, `EnhancementLevel` с валидацией в конструкторе/сеттере).
- P1-11: сuzить фасад `Player` — новые вызовы идут к компонентам (`PlayerCombatStats` и т.п.); отметить `[Obsolete]` pass-through свойства.

### Фаза 3 — Сервер DI / ясность (недели 5-7)
- P1-2: завершить удаление `Program.Services` статик; все сервисы через конструктор `GameServices`; убрать `Pathfinding.Services` back-ref (передавать зависимости явно).
- P2-8: удалить мёртвые `RunCombatLoop`/`RunHazardTickLoop`; документировать единый unified loop.
- Покрыть сервисы unit-тестами через DI (без статик-зависимостей).

### Фаза 4 — Клиент (недели 7-10)
- P0-2: заменить ~90 лямбда-подписок на method-group (или слабые ссылки/IMediator), чтобы `UnsubscribeAll` работал; добавить тест на утечку при logout→login.
- P1-3: вынести wiring/оркестрацию из `GameScreen` (VM/Mediator слой между `GameClient` и окнами).
- P1-4/5: перейти на viewport/3×3 стриминг секторов, убрать полную презагрузку 510; удалить дубликат `SectorData` в `MinimapRenderer` (рисовать из `MapRenderer`).
- P1-6: диспозить анимационные `Texture2D` и шрифты в `SpriteCache.Unload`.
- P2-3/4: порт реконнекта из логина; унификация toggle-маппинга в `GameInputHandler`.

### Фаза 5 — Пайплайн / тесты / Editor (недели 10-13)
- P0-3 + P1-9: разделить authoring и live `content.db` (Editor работает с изолированной копией/branch; staging + diff до применения на сервере); вынести `content.db` из git (LFS или build-time fetch).
- P1-9: подписанные/аутентифицированные клиентские апдейты (code signing + TLS или pinned pubkey); minVersion floor (защита от downgrade).
- P1-7/8: вынести общий read/write репозиторий в `Shared`, используемый Server и Editor; генерировать колонки из модели/каталога; заменить DELETE+INSERT на row-level upsert.
- P2-5: транзакция в `DialogueEditorWindow.SaveDialogue`.
- P2-9: rollback-копия при деплое, не-root деплой, не паковать локальный game.db.
- Расширить `LostAndDivine.Tests` (уже 223 теста) на миграции, утечки клиента, Editor-DB-drift.

## 5. Вопросы к заказчику

1. **Целевая CCU** — какой пик одновременных игроков на один инстанс сервера (1-50 / 50-500 / 500+)? От этого зависит приоритет P1-1 (глобальный лок), P2-7 (BroadcastMap) и лимит соединений.
2. **Совместимость сохранений** — допустим ли breaking-change миграций (сброс/конвертация старых персонажей), или нужна строгая обратная совместимость save-формата? Влияет на P2-2 (инварианты в моделях) и схему БД.
3. **Приоритет фич vs стабильность** — готовы ли заморозить новые фичи на 1-2 спринта для фаз 0-1 (безопасность/данные), или стабильность вторична относительно скорости фич?
4. **content.db как источник правды** — контент правится только через Editor и коммитится, или есть runtime-мутации (NPC-плейсмент, миры) на живом сервере? Определяет P0-3/P1-9 (staging vs live).
5. **Дистрибуция клиента** — есть ли подписанный установщик / возможность принудительного обновления до подписанного апдейтера? Без этого P1-9 (RCE) не закрывается ретроактивно.
6. **Целевые платформы клиента** — только Windows (MonoGame/Desktop GL) или кроссплатформа? Влияет на SpriteCache/GPU-стратегию (P1-6).
